5. Choix d'outils justifiés

  • Source — GitHub : centralisation du code et déclenchement `push`. GitHub Actions est cohérent avec l'hébergement du dépôt.
  • Setup — `actions/checkout@v2` et `actions/setup-node@v2` : standard pour récupérer le code et préparer l'environnement Node de manière reproductible.
  • Build — `npm install` + `cd frontend && npm run build` : permet de construire le front React et de préparer le runtime backend. Le choix de `npm` est naturel puisque le projet contient un `package-lock.json` et des scripts racines partagés.
  • Validation — tests actuellement désactivés, mais le pipeline doit évoluer vers `npm test` et l’ajout de contrôles statiques (lint / audit de sécurité) pour réduire les risques avant déploiement.
  • Deploy — `appleboy/ssh-action@master` + `pm2 restart all` : déploiement simple via SSH vers une machine distante. Ce modèle convient pour un PoC ou un environnement d’hébergement géré, mais il faudra envisager un mécanisme plus sécurisé (`SSH key`, `deploy user`, ou `GitHub Deploy Keys`) et un déclencheur multi-environnement si le projet monte en charge.

Recommandation : ajouter une étape de test fonctionnel avant `Deploy`, et transformer la commande SSH en déploiement immutable si l’infrastructure évolue vers Kubernetes ou un fournisseur cloud.
